# Книга заклинаний — расширение для Owlbear Rodeo

Версия 1.1.1. Русский интерфейс, каталог для игроков и управление пользовательскими заклинаниями для мастера.

## Возможности

- Поиск по названию и описанию.
- Фильтры по уровню, классу и школе магии.
- Сортировка по названию, уровню, классу и школе.
- Карточка заклинания с описанием, временем накладывания, дальностью, компонентами, длительностью, концентрацией и ритуалом.
- Кнопки броска урона для SRD-заклинаний: формулы урона по уровням ячеек и уровням персонажа берутся из структурированных данных API.
- Встроенный бросатель без анимации: поддерживает формулы вроде `8d6`, `2d6+1d8+4`; показывает каждый результат и сумму.
- Бросок отправляется участникам комнаты через OBR Broadcast; фоновая страница расширения показывает уведомление, даже когда окно каталога закрыто (при условии, что расширение включено в комнате).
- Открытая база SRD 2014 или SRD 2024 из D&D 5e API.
- Импорт пользовательских записей из JSON, CSV, Markdown и TXT доступен только мастеру.
- Экспорт пользовательской библиотеки в `custom-spells.json` для публикации всем участникам комнаты.

## Установка через GitHub Pages

1. Создай новый публичный репозиторий GitHub с именем `Spellbook-OWR` (или измени адреса в `manifest.json` под своё имя и репозиторий).
2. Загрузи в корень репозитория все файлы из этого архива, не сам ZIP.
3. Включи GitHub Pages: **Settings → Pages → Deploy from a branch → main → /(root) → Save**.
4. Дождись публикации.
5. Проверь страницу `https://psaa00.github.io/Spellbook-OWR/manifest.json`.
6. В Owlbear Rodeo открой **Profile → Extensions → Add Custom Extension** и вставь эту ссылку.

Если используешь другое имя пользователя или репозитория, замени адреса в `manifest.json`, включая `background_url`.

## Как игроки увидят пользовательские заклинания

GitHub Pages — статический хостинг, поэтому расширение не может безопасно записывать новый файл прямо в репозиторий. Для публикации предусмотрен простой поток:

1. Мастер открывает расширение в Owlbear Rodeo.
2. В блоке **Управление библиотекой** нажимает **Импортировать файл** и загружает JSON, CSV, MD или TXT.
3. Черновик хранится в локальном браузере мастера.
4. Мастер нажимает **Скачать custom-spells.json**.
5. На GitHub открывает репозиторий расширения, выбирает **Add file → Upload files**, загружает скачанный `custom-spells.json` в корень и подтверждает замену существующего файла через Commit changes.
6. Игроки обновляют каталог кнопкой ↻ или закрывают и снова открывают расширение. Их браузеры загрузят опубликованный файл.

Так содержимое будет общим. Учти: всё, что опубликовано в публичном репозитории, доступно любому человеку в интернете, а не только игрокам этой комнаты. Не публикуй в нём материалы, на распространение которых у тебя нет прав.

## Формат JSON

Можно загрузить массив:

```json
[
  {
    "name": "Название заклинания",
    "level": 1,
    "school": "Ограждение",
    "classes": ["Жрец", "Паладин"],
    "castingTime": "1 действие",
    "range": "На себя",
    "components": ["В", "С"],
    "duration": "Мгновенная",
    "description": "Текст описания заклинания.",
    "source": "Домашняя библиотека"
  }
]
```

Или объект с массивом `spells`. Поддерживаются синонимы полей: `desc`/`description`/`Описание`, `classes`/`class`/`Классы`, `school`/`Школа`, `level`/`Уровень`.

CSV: первая строка — заголовки столбцов. Рекомендуемые колонки: `name,level,school,classes,description,castingTime,range,components,duration,concentration,ritual,source`. Несколько классов указывай через `;` или `|`. Если сам CSV использует `;` как разделитель столбцов, для списка классов используй `|`.

Markdown/TXT: один заголовок `# Название заклинания` или `## Название заклинания` на запись. Сразу после заголовка можно указать поля отдельными строками, например `Уровень: 2`, `Школа: Воплощение`, `Классы: Волшебник; Чародей`, `Время накладывания: 1 действие`, `Дальность: 18 метров`, `Длительность: Мгновенная`. Остальной текст записи используется как описание.

## Источник SRD

Кнопка обновления загружает записи из открытого D&D 5e API: `https://www.dnd5eapi.co/api/2014` (SRD 5.1) или `https://www.dnd5eapi.co/api/2024` (SRD 5.2). Это **не полный каталог всех опубликованных заклинаний D&D**: API включает только контент соответствующего System Reference Document.

SRD 5.1 и SRD 5.2 опубликованы Wizards of the Coast под Creative Commons Attribution 4.0 International (CC BY 4.0). При использовании содержимого SRD сохраняй указание авторства и лицензию. Подробности: https://www.dndbeyond.com/srd

D&D 5e API: https://docs.dnd5eapi.co/ · API project: https://github.com/5e-bits/5e-srd-api

## Ограничения и примечания

- Клиент Owlbear SDK подгружается с CDN `esm.sh` (пакет `@owlbear-rodeo/sdk` версии 3.1.0). Для корректного определения роли игрока/мастера браузеру нужен доступ к этому CDN.
- Открытая база SRD загружается отдельно в браузер каждого участника и кэшируется локально. При первом получении полной базы может потребоваться время и соединение с API. В API на момент разработки есть английский, французский и бразильский португальский, но нет русского перевода; названия и описания из SRD поэтому могут отображаться на английском.
- Пользовательские заклинания загружаются из публичного `custom-spells.json` рядом с расширением. После замены файла на GitHub игрокам достаточно обновить каталог.
- Автоматический импорт/скрейпинг dnd.su не включён: документированный публичный API и разрешение на переиздание полного каталога не подтверждены. Можно загружать собственные JSON/CSV/MD/TXT-файлы, если у тебя есть право распространять их содержимое.
- Расширение не отправляет библиотеку в метаданные комнаты Owlbear Rodeo: room metadata имеет ограничение 16 kB, что слишком мало для полной книги заклинаний. Общая пользовательская библиотека публикуется отдельным JSON-файлом на GitHub Pages.
- Проверка работы внутри реальной комнаты Owlbear Rodeo всё равно нужна: здесь можно проверить файлы и логику, но не подключиться к твоей комнате.

## Броски урона

Кнопка броска появляется, если источник содержит структурированные поля урона SRD или если пользовательское заклинание импортировано с полем `damageFormula` / `Урон`. Для заклинаний SRD выбирается подходящий уровень ячейки или уровень персонажа (для заговоров), после чего расширение бросает кости в браузере. Генерация использует `crypto.getRandomValues` с отбраковкой смещения при преобразовании в диапазон граней.

Результат добавляется в локальную историю расширения и отправляется другим участникам комнаты через `OBR.broadcast`. Фоновая страница (`background.html`) слушает отдельный канал и показывает уведомление Owlbear Rodeo даже если окно каталога закрыто. Расширение должно быть включено в комнате у тех участников, которые должны получать результаты. Сообщения Broadcast временные и не являются долговременным журналом бросков. Если канал OBR ещё не подключён, расширение ждёт готовности SDK и повторяет отправку до трёх раз; при окончательном сбое бросок всё равно остаётся в локальной истории.

Официальное расширение Dice Owlbear Rodeo не предоставляет документированного публичного API для постановки броска из стороннего расширения. Поэтому этот бросатель работает автономно и выводит результат числом, без физической 3D-анимации.
